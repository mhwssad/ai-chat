# Agent Runtime Roadmap Requirements

## 1. 目标

Agent Runtime 是第二、三阶段的核心演进方向。它应基于 MVP 的聊天、模型、工具注册表、记忆、权限和审计能力继续扩展，而不是另起一套独立系统。

该文档用于定义长期能力边界，避免第一阶段过度实现。

## 2. 第二阶段目标

第二阶段目标是让工具、MCP、skills 和记忆真正进入 Agent 执行流程。

### 2.1 工具调用链

Agent 应能根据任务上下文选择工具、执行工具、读取结果并继续推理。

所有工具调用必须经过统一工具注册表和权限策略。

### 2.2 MCP 管理增强

系统应支持 MCP server 状态查看、连接诊断、工具发现结果展示、启用禁用和调用日志查看。

### 2.3 Skills 管理增强

系统应支持 skills 列表、说明查看、启用禁用、调用记录和适用场景展示。

### 2.4 长期记忆

系统应支持用户可控的长期记忆，包括查看、删除、禁用、来源解释和检索命中展示。

### 2.5 Agent 调试视图

系统应提供 Agent 实验室视图，展示模型请求、工具调用、权限判断、记忆命中、耗时、错误和最终结果。

## 3. 第三阶段目标

第三阶段目标是形成完整的本地 Agent 工作台。

### 3.1 后台任务队列

系统应支持长任务进入后台执行，并可查询任务状态。

### 3.2 任务取消与恢复

系统应支持取消运行中任务，并为长任务恢复预留状态保存机制。

### 3.3 多步骤 Agent 编排

系统应支持更复杂的任务计划、步骤执行、工具选择、失败重试和结果总结。

### 3.4 项目知识库

系统应支持索引项目文档、笔记和可选代码内容，并在 Agent 执行时检索相关上下文。

### 3.5 更强安全隔离

系统应逐步增强工具执行隔离，包括更严格权限策略、确认流程、执行超时和可选沙箱。

## 4. Agent 执行状态

Agent 执行过程应有明确状态，包括待开始、运行中、等待用户确认、已取消、失败、成功和部分成功。

状态变化应写入运行态存储，并可在 Web 或 CLI 中查看。

## 5. 用户确认

当 Agent 需要执行高风险工具时，系统应暂停执行并请求用户确认。

确认结果应进入审计日志，并影响后续策略。

## 6. 可观察性

Agent Runtime 应记录关键执行轨迹，包括任务输入、模型选择、推理步骤摘要、工具调用、记忆检索、权限决策、错误和输出。

轨迹应适合调试，但不应泄漏 API Key 或其他敏感信息。

## 7. 与 MVP 的关系

Agent Runtime 必须复用 MVP 的模型接口、工具注册表、记忆接口、存储模块、权限策略和审计机制。

如果某个 Agent 能力需要绕过这些基础模块，说明基础边界需要调整，而不是在 Agent Runtime 中复制一套逻辑。

## 8. 验收方向

- Agent 可以完成至少一个需要工具调用的多步骤任务。
- 高风险工具调用会触发确认或拒绝。
- Agent 实验室可以展示执行轨迹。
- 长期记忆命中可以被查看和解释。
- 后台任务可以查看状态。
- 任务失败后可以看到失败步骤和错误原因。
