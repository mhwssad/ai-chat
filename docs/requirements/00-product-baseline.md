# AI 工作台产品基线

## 1. 目标

本项目定位为本地优先的 AI 工作台与 Agent 能力平台。系统应为个人开发者和高级使用者提供统一的模型接入、对话、工具执行、知识检索、任务运行和状态观察能力。

该产品既不是单纯的聊天页面，也不是只面向终端的一组脚本命令。系统应提供可扩展、可观察、可审计、可演进的运行环境，使 Web、TUI 和 API 可以围绕同一套核心能力协同工作。

## 2. 目标用户

系统主要面向以下用户：

1. 本地开发者，希望统一管理多个模型供应商、工具和运行上下文。
2. Agent 能力实验者，希望观察任务执行、工具调用、记忆命中和错误链路。
3. 高级个人用户，希望在本地环境中使用 AI 工作台处理对话、知识检索和任务协助。

## 3. 核心使用场景

系统应支持以下核心场景：

1. 用户在 Web 中创建会话、发送消息、切换模型并查看历史消息。
2. 用户在 TUI 中完成业务交互，包括对话、工具状态查看、记忆管理、RAG 操作、Agent 任务执行和系统操作。
3. 用户通过 API 将聊天、任务、媒体和配置能力接入外部前端或自动化流程。
4. 用户接入多个模型供应商，并在运行时切换模型或观察模型状态。
5. 用户通过统一 Tool Registry 使用内置工具、MCP 工具和 Skill 派生能力。
6. 用户在后续阶段通过 Agent Runtime 执行多步骤任务，并查看执行轨迹与错误信息。

## 4. 总体能力范围

系统总体能力应覆盖以下领域：

1. Chat and Models
2. Tools, MCP and Skills
3. Memory and RAG
4. Agent Runtime
5. Interaction Surfaces: Web / TUI / API
6. Storage, Config and Audit
7. System Architecture and Data Model

## 5. 非目标

当前产品基线不包含以下目标：

1. 多用户账号体系和团队协作空间。
2. 云端同步和远程托管运行环境。
3. 面向普通消费者的极简聊天产品定位。
4. 与当前项目边界无关的通用企业工作流平台能力。

## 6. 关键术语

- Web：浏览器交互界面。
- TUI：Terminal User Interface，终端工作台。
- API：对外服务接口。
- Tool Registry：统一工具注册表。
- Agent Runtime：任务执行与多步骤编排运行时。
- Current Baseline：当前阶段可作为事实参考的实现与约束。
- Target State：文档定义的目标产品状态。

## 7. 成功标准

当项目达到基线要求时，应满足以下判断：

1. 用户可以通过 Web、TUI 或 API 访问同一套核心能力。
2. 模型、工具、记忆、RAG 和 Agent 不再是相互割裂的子系统。
3. 关键行为具有统一的状态、错误、权限和审计语义。
4. 文档结构能够支撑后续需求扩展，而不需要反复推翻重写。
