# Web And CLI Requirements

## 1. 目标

Web 和 CLI 是同一套 AI 工作台核心能力的两个入口。两者应共享聊天、模型、工具、存储、权限和审计服务，避免重复实现。

MVP 以 Web 聊天体验为主，以 CLI 开发者入口为辅。

## 2. 共享核心

Web 和 CLI 不应直接实现供应商调用、上下文组装、工具执行或存储逻辑。

共享核心应提供异步接口，包括聊天请求、供应商管理、模型管理、模型列表、供应商状态、会话管理、工具列表、配置检查和审计查询。

## 3. Web 需求

### 3.1 聊天页面

Web 应支持会话创建、消息发送、流式输出、模型选择、历史消息查看和错误展示。

### 3.2 会话侧栏

Web 应支持查看会话列表、打开已有会话和显示最近更新时间。

### 3.3 模型选择

Web 应显示当前模型，并允许用户选择其他已启用模型。

模型切换应只影响后续消息。

### 3.4 状态展示

Web 应能显示供应商状态、工具状态和基础错误信息。

高级信息应可折叠展示，避免默认界面过载。

### 3.5 Agent 实验室入口

MVP 可提供 Agent 实验室入口或占位页面，用于后续展示工具调用轨迹、记忆命中和任务执行状态。

## 4. CLI 需求

### 4.1 服务启动

CLI 应支持启动 Web 服务或本地工作台服务。

### 4.2 一次性聊天

CLI 应支持发送一次性聊天请求，并可指定模型。

### 4.3 配置检查

CLI 应支持检查数据库配置是否完整、供应商是否启用、默认模型是否可用、API Key 环境变量或本地安全存储引用是否存在。

### 4.4 模型与供应商

CLI 应支持列出、新增、修改、禁用和删除供应商、模型和默认模型。

### 4.5 工具诊断

CLI 应支持列出工具注册表中的工具及权限声明。

## 5. 体验原则

Web 默认应简单，不把所有工程信息暴露给普通聊天流程。

CLI 默认应清晰，错误输出应适合开发者定位问题。

两者都应提供足够信息帮助用户判断问题是配置错误、供应商错误、模型错误、存储错误还是工具错误。

## 6. 验收标准

- Web 能完成主要聊天流程。
- CLI 能发起一次聊天请求。
- Web 和 CLI 使用同一套模型列表。
- Web 和 CLI 对同一配置错误给出一致判断。
- Web 的模型切换与 CLI 指定模型遵循同一规则。
- 工具列表在 Web 和 CLI 中来源一致。
