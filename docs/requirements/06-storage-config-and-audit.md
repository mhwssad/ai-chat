# Storage, Config And Audit Requirements

## 1. 目标

存储、配置和审计模块用于保证系统行为可理解、可恢复、可追踪。

SQLite 负责系统业务配置和运行态数据，审计日志负责记录关键行为。配置文件只保留启动期最小引导配置，例如数据库路径、日志级别和可选环境变量覆盖。

## 2. 数据库配置

### 2.1 配置内容

数据库应管理供应商、模型、默认模型、MCP server、skills 启用策略、安全策略和基础系统设置。Web 和 CLI 应通过共享核心服务对这些配置进行增删改查。

### 2.2 API Key

数据库不应保存明文 API Key。供应商和外部服务配置中必须保存加密后的 API Key 或加密凭据。

### 2.3 配置校验

系统应校验数据库配置完整性、必填字段、重复标识、默认模型是否存在、启用供应商是否具备必要凭据、模型是否属于有效供应商。

### 2.4 配置来源

MVP 中 SQLite 是业务配置的 source of truth。Web 和 CLI 应能读取、展示、校验并写回供应商、模型、MCP server、skills 和安全策略配置。

### 2.5 配置文件边界

配置文件只用于应用启动所需的最小信息，不应保存供应商、模型、MCP server、skills 或安全策略等可管理业务配置。

## 3. SQLite 数据

### 3.1 数据范围

SQLite 应保存供应商、模型、默认模型、MCP server、skills、安全策略、会话、消息、模型调用记录、工具调用日志、权限决策、记忆索引和系统运行状态。

### 3.2 会话与消息

会话和消息应支持历史查看、继续对话、错误状态保存和模型使用记录。

### 3.3 调用记录

模型调用和工具调用应记录时间、来源、输入摘要、输出摘要、耗时、状态和错误。

### 3.4 迁移

数据库 schema 应支持版本化迁移。后续新增字段不应破坏已有会话数据。

## 4. 审计日志

### 4.1 审计范围

审计日志应覆盖模型调用、工具调用、MCP 调用、skills 调用、权限决策、记忆写入、配置检查和关键错误。

### 4.2 审计字段

审计记录至少包含时间、事件类型、来源模块、目标能力、输入摘要、输出摘要、状态、耗时、权限决策和错误信息。

### 4.3 隐私处理

审计日志不应无条件保存完整敏感输入。对于 API Key、密钥、文件内容和长文本，应使用摘要、脱敏或引用方式记录。

## 5. 数据边界

业务配置数据和运行态数据都保存在 SQLite，但应通过不同表和服务边界分离。配置表描述用户希望系统如何运行，运行态表记录系统实际发生了什么。

这条边界应在 Web、CLI 和核心服务中保持一致。

## 6. 备份与可迁移

本地数据应尽量使用可备份、可迁移的结构。SQLite 数据应通过 schema、版本表和导出能力支持后续迁移。启动期配置文件应保持极简，避免承载业务状态。

## 7. 验收标准

- 数据库配置可以被读取、写入和校验。
- 缺失 API Key 环境变量时能给出清晰错误。
- 会话和消息能保存到 SQLite 并重新加载。
- 模型调用和工具调用能生成审计记录。
- 审计日志不会保存明文 API Key。
- 配置表和运行态表边界清晰，不会混写业务含义。
