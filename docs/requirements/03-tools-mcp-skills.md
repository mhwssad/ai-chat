# Tools, MCP And Skills Requirements

## 1. 目标

工具、MCP 和 skills 应通过统一工具注册表进入系统。Agent 和聊天流程只面对工具能力，不直接区分能力来自内置工具、MCP server 还是 skill。

MVP 重点是定义统一边界和最小可用注册机制，第二阶段再增强动态发现、管理界面和复杂调用链。

## 2. 统一工具注册表

### 2.1 工具元数据

每个工具应声明以下信息：

- 工具标识。
- 显示名称。
- 描述。
- 来源类型。
- 来源标识。
- 输入参数 schema。
- 输出结果 schema 或说明。
- 权限需求。
- 是否启用。
- 是否支持异步执行。
- 超时策略。

### 2.2 来源类型

工具来源至少包括：

- 内置工具。
- MCP 工具。
- Skill 派生工具。

系统后续可扩展更多来源，但不应影响 Agent 调用工具的统一方式。

### 2.3 工具状态

工具应有可观察状态，包括已注册、已启用、已禁用、不可用、执行中、执行失败。

MVP 应支持列出工具和启用状态。后续支持更完整运行态管理。

## 3. 内置工具

内置工具用于提供系统自带的基础能力。

MVP 可以只提供少量安全工具或占位工具，用于验证工具注册表、权限声明、审计日志和调用流程。

内置工具不得绕过权限策略。

## 4. MCP 需求

### 4.1 MCP server 配置

MCP server 配置应来自配置文件。配置应包含 server 标识、启动方式或连接方式、启用状态、环境变量引用和权限策略。

### 4.2 工具发现

MCP 模块应能连接启用的 server，并发现其提供的工具。

发现到的 MCP 工具应转换为统一工具元数据，并注册到工具注册表。

### 4.3 连接诊断

MVP 至少应支持连接检查和错误展示。错误应区分配置错误、启动失败、连接失败、协议错误和工具发现失败。

### 4.4 调用日志

MCP 工具调用应记录来源 server、工具名称、输入摘要、输出摘要、耗时、错误和权限决策。

## 5. Skills 需求

### 5.1 Skill 发现

系统应能发现本地可用 skills，并读取其名称、描述、适用场景和能力边界。

### 5.2 Skill 到工具

当 skill 提供可执行能力时，应通过工具注册表暴露，而不是直接由 Agent 绕过注册表调用。

### 5.3 Skill 管理

MVP 可只支持发现和启用状态展示。后续支持安装、禁用、版本信息、说明查看和调用记录。

## 6. 权限需求

工具必须声明权限需求。权限至少覆盖只读、网络访问、文件读取、文件写入、命令执行、外部服务调用、记忆写入和高风险本地操作。

系统应根据权限策略返回允许、拒绝或询问用户。

## 7. Agent 调用边界

Agent 不应直接调用任意函数或外部服务。Agent 应通过工具注册表获取可用工具，并通过统一执行入口调用工具。

工具执行入口负责权限判断、参数校验、超时控制、审计日志和错误归一化。

## 8. 验收标准

- 系统可以列出已注册工具。
- 每个工具可以显示来源和权限需求。
- MCP 工具可以被转换为统一工具描述。
- Skill 派生能力不会绕过工具注册表。
- 工具调用会生成审计日志。
- 高风险权限可以被策略拒绝或标记为需要询问。
