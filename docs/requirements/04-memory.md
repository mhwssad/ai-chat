# Memory Requirements

## 1. 目标

记忆模块用于帮助系统在对话、任务和项目上下文中保留必要信息。记忆必须可解释、可控制、可关闭，不能成为不可见的黑箱。

MVP 只实现会话内记忆和长期记忆接口预留。长期用户记忆和项目知识记忆进入后续阶段。

## 2. 记忆分层

### 2.1 会话内记忆

会话内记忆只在当前会话中生效。它包括消息历史、当前模型、工具调用摘要、用户在当前会话中明确提供的上下文和系统运行状态。

会话内记忆是 MVP 必做能力。

### 2.2 长期用户记忆

长期用户记忆用于保存跨会话使用的用户偏好、常用约定、项目背景和工作方式。

长期用户记忆不是 MVP 必做能力，但 MVP 应预留接口和数据边界。

### 2.3 项目知识记忆

项目知识记忆用于索引项目文档、笔记和可选代码内容，为聊天或 Agent 提供检索上下文。

项目知识记忆属于后续阶段，不应阻塞 MVP。

## 3. 会话内记忆需求

### 3.1 上下文来源

会话内记忆来源包括当前会话消息、工具结果摘要、模型选择、用户显式说明和系统提示。

### 3.2 上下文控制

系统应能根据模型上下文长度控制传入模型的历史消息数量和摘要内容。

### 3.3 工具结果摘要

工具调用结果可能较长。系统应保存完整结果或引用，同时为模型上下文生成较短摘要。

### 3.4 错误状态

如果工具或模型调用失败，错误状态可进入会话上下文，但应避免重复污染后续提示。

## 4. 长期记忆接口

MVP 应预留长期记忆接口，包括写入、读取、搜索、删除、禁用和列出来源。

接口存在不代表 MVP 必须自动写入长期记忆。

## 5. 用户控制

用户应能关闭长期记忆写入。后续实现长期记忆后，用户应能查看、编辑和删除记忆。

任何自动记忆写入都应记录来源、时间、触发原因和所属会话。

## 6. 隐私要求

记忆默认保存在本地。未经用户明确启用，不应将记忆上传到外部服务。

涉及项目文件、聊天历史、工具输入和用户偏好时，应优先使用最小必要内容。

## 7. 审计要求

长期记忆写入、删除、检索命中和项目知识检索都应记录审计信息。

MVP 至少应记录会话内上下文组装的关键来源，便于调试。

## 8. 验收标准

- 会话可以基于历史消息继续对话。
- 工具结果可以以摘要形式进入后续上下文。
- 长期记忆接口边界清晰，但默认不自动写入。
- 用户可以关闭未来长期记忆能力。
- 记忆相关行为不会绕过审计策略。
