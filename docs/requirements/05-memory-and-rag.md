# 记忆与 RAG 需求

## 1. 目标

系统应提供可解释、可控制、可关闭的记忆与知识检索能力，使聊天和 Agent 可以在必要时使用上下文增强，而不会形成不可见的黑箱行为。

## 2. 范围与边界

本模块包括：

1. 会话内记忆。
2. 长期记忆边界。
3. 项目知识记忆与 RAG。
4. 记忆与检索的用户控制、隐私和审计。

本模块不负责：

1. 模型供应商管理。
2. 具体工具执行逻辑。
3. 独立任务编排状态机。

## 3. 会话内记忆

系统应支持以下会话内记忆来源：

1. 当前会话消息历史。
2. 当前模型选择。
3. 工具调用摘要。
4. 系统提示与运行上下文。
5. 与当前任务相关的短期上下文信息。

系统应根据模型上下文长度限制控制注入内容规模。

## 4. 长期记忆

系统应为长期记忆预留正式产品边界，包括：

1. 写入。
2. 读取。
3. 搜索。
4. 删除。
5. 禁用。
6. 来源说明。

是否自动写入长期记忆由阶段目标控制，不应默认隐式开启不可见写入。

## 5. 项目知识记忆与 RAG

系统应支持以下 RAG 能力：

1. 文件与目录索引。
2. 会话级与全局级作用域。
3. 向量检索。
4. 混合检索。
5. 上下文构建。
6. 文档删除、清空与会话级清理。

RAG 应被视为上下文增强能力，而不是独立脱离聊天与 Agent 的子系统。

## 6. 用户控制

系统应允许用户：

1. 控制记忆写入行为。
2. 查看和删除记忆。
3. 区分会话级与全局级知识作用域。
4. 查看文档、检索和上下文构建结果。

## 7. 隐私与审计

系统应满足以下要求：

1. 记忆与知识默认本地保存。
2. 敏感内容不应无条件写入长期存储。
3. 记忆写入、删除、检索命中和知识库清理应保留审计边界。
4. 上下文构建应可解释其来源类型。

## 8. 约束与风险

1. 如果记忆写入不可解释，用户无法信任长期上下文。
2. 如果 RAG 与会话作用域混乱，会导致结果污染和调试困难。
3. 如果记忆和检索行为缺少审计，后续 Agent 调试会失真。

## 9. 验收标准

1. 会话可基于历史上下文继续对话。
2. RAG 可完成索引、检索和上下文构建主流程。
3. 记忆与 RAG 行为具备清晰的作用域边界。
4. 用户可对关键记忆与知识库操作进行控制。
