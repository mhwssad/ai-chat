# MVP Task List

## 1. 使用说明

本文档用于跟踪 MVP 实施进度，来源于 `docs/plans/01-mvp-implementation-plan.md`。

状态约定：

- `[ ]`：未开始。
- `[x]`：已完成并通过基础验证。
- `[~]`：进行中或部分完成。
- `[!]`：被阻塞，需要先解决依赖、设计或测试问题。

更新规则：

- 每完成一个任务，应同步勾选对应条目。
- 如果任务实现偏离需求文档，应先更新需求或计划文档。
- 每个阶段完成前，应至少跑一次对应验证命令或记录无法验证的原因。

## 2. 阶段 0：基线整理

目标：确认当前项目结构、已有聊天能力、配置方式、数据库状态和测试入口。

- [ ] 梳理当前目录结构和模块职责。
- [ ] 确认 Web 服务入口。
- [ ] 确认 CLI 入口。
- [ ] 确认当前聊天请求调用链。
- [ ] 确认现有配置文件和环境变量读取方式。
- [ ] 确认当前模型供应商实现。
- [ ] 确认当前数据存储方式。
- [ ] 确认当前数据库初始化和迁移方式。
- [ ] 记录当前可运行命令。
- [ ] 记录当前测试命令和已知测试失败原因。

验收：

- [ ] 能说明聊天请求从入口到模型调用的路径。
- [ ] 能说明会话和消息当前是否已持久化。
- [ ] 能说明哪些代码可复用、哪些需要重构。

目标：建立多供应商和模型管理核心抽象。

- [ ] 定义供应商配置结构。

- [ ] 实现默认模型解析。
- [ ] 实现统一模型调用接口。
- [ ] 实现供应商错误归一化。
- [ ] 补充配置和模型相关测试。

验收：

- [ ] 可以从配置文件读取供应商和模型。

- [ ] 实现创建会话。

- [ ] 接入统一模型调用接口。
- [ ] 实现流式响应事件。
- [ ] 实现助手消息状态更新。
- [ ] 实现模型调用失败状态保存。
- [ ] 预留取消接口。
- [ ] 接入会话内记忆上下文来源。
- [ ] 补充聊天核心测试。

验收：

- [ ] 聊天核心可以在不依赖 Web 的情况下被调用。
- [ ] 一次聊天会保存用户消息和助手消息。

- [ ] 模型调用失败时会保存错误状态。
- [ ] 模型切换只影响后续消息。

## 9. 阶段 7：审计、错误与可观察性

目标：让 MVP 的关键行为可追踪、可诊断、可恢复。

- [ ] 统一模型调用错误结构。
- [ ] 统一工具调用错误结构。
- [ ] 记录模型调用审计日志。
- [ ] 记录工具调用审计日志。
- [ ] 记录权限决策。
- [ ] 在 Web 中展示用户可理解错误。
- [ ] 在 CLI 中展示开发者可诊断错误。
- [ ] 对日志中的 API Key 和敏感内容做脱敏。
- [ ] 补充审计与错误处理测试。

验收：

- [ ] 模型认证失败、限流、网络错误可以区分。
- [ ] 工具执行失败可以记录来源和错误。
- [ ] 审计日志包含时间、来源、状态、耗时和错误摘要。
- [ ] 敏感信息不会以明文进入日志。
